Guía de migración del servicio de pedidos — escenario ficticio del laboratorio

Regla de migración M01: el sistema antiguo y el nuevo deben aceptar el mismo identificador de pedido. Antes de trasladar un lote, el equipo guarda una copia del contrato de entrada y prepara ejemplos con pedidos abiertos, cerrados y cancelados. El objetivo inicial es preservar el comportamiento observable. Renombrar una clase no justifica cambiar una regla comercial. Toda diferencia deliberada se registra como una decisión independiente, con responsable y una prueba que permita verificarla.

Patrón aprobado P01: separar adaptación de datos y lógica de negocio. Un adaptador convierte la fecha recibida al formato interno; el servicio de dominio decide si el pedido puede confirmarse. La migración conserva los valores originales para comparar los resultados de ambos sistemas. Las fechas sin zona horaria se rechazan con un mensaje explícito; no se supone silenciosamente la zona del servidor. El equipo usa ejemplos sintéticos y nunca copia datos de clientes a este laboratorio.

Error conocido E01: algunos lotes históricos contienen el mismo evento dos veces. El consumidor nuevo registra la clave del evento procesado para evitar un segundo descuento de inventario. La prueba reproduce dos entregas idénticas y comprueba que existe un solo movimiento. Si dos eventos comparten clave pero tienen contenido distinto, el lote se detiene para revisión; no se elige arbitrariamente uno de ellos. La idempotencia se valida antes de ampliar el volumen de pedidos migrados.

Decisión arquitectónica A01: migrar por lotes pequeños y conservar una ruta de reversión. Cada lote registra versión del código, contrato utilizado, cantidad de registros y resultado de validación. Ante una discrepancia, se detiene el siguiente lote y se compara el caso mínimo que reproduce el problema. No se borra el historial anterior. El cierre de la migración requiere evidencia de equivalencia funcional y aprobación del equipo responsable. Este documento es original, educativo y no describe políticas reales de ninguna organización.
